# Athishay.dev Copywriting Guidelines

Version: 1.0

---

# Philosophy

The purpose of writing is not to impress.

The purpose of writing is to communicate clearly.

Every sentence should help visitors understand who Athishay Jain is, what he builds, and why it matters.

The copy should feel human, thoughtful, and honest.

---

###########################################################
# BRAND VOICE
###########################################################

The website should sound:

✓ Curious

✓ Confident

✓ Honest

✓ Practical

✓ Thoughtful

✓ Engineering-first

✓ Calm

Never sound:

✗ Corporate

✗ Salesy

✗ Buzzword-heavy

✗ Overconfident

✗ Fake humble

✗ AI-generated

---

###########################################################
# WRITING PRINCIPLES
###########################################################

Write like explaining your work to another engineer.

Use short sentences.

Use active voice.

Remove unnecessary adjectives.

Prefer clarity over cleverness.

Every paragraph should have one idea.

---

###########################################################
# SENTENCE LENGTH
###########################################################

Ideal

12–20 words

Maximum

30 words

If a sentence exceeds 30 words,

rewrite it.

---

###########################################################
# PARAGRAPHS
###########################################################

Maximum

3–4 lines

White space improves readability.

Avoid walls of text.

---

###########################################################
# HEADLINES
###########################################################

Should answer one question.

Examples

Building products that solve real problems.

Things I've Built.

How I Work.

Current Focus.

Let's Build Something.

Avoid

Welcome to my portfolio.

Hi, I'm Athishay.

Passionate Engineer.

Innovative Solutions.

---

###########################################################
# SUBHEADINGS
###########################################################

Support the headline.

Not repeat it.

Example

Heading

Things I've Built

Subheading

A collection of products, experiments, and ideas that solve real problems.

---

###########################################################
# PROJECT WRITING
###########################################################

Every project follows the same story.

Problem

↓

Context

↓

Research

↓

Solution

↓

Architecture

↓

Development

↓

Challenges

↓

Results

↓

Lessons Learned

↓

Future Improvements

Never begin with technology.

Begin with the problem.

---

###########################################################
# CASE STUDY STYLE
###########################################################

Bad

"I developed an ESP32-based IoT monitoring system."

Good

"I wanted a UPS that could do more than provide backup power. Existing systems offered very little visibility, so I built one that users could monitor and control remotely."

Always explain

Why

before

How.

---

###########################################################
# ABOUT WRITING
###########################################################

Focus on motivation.

Not personality traits.

Instead of

"I am hardworking."

Show

"I enjoy learning whatever is necessary to build a complete product."

---

###########################################################
# NUMBERS
###########################################################

Use real numbers.

30+ IoT Projects

100+ STEM Kits

6+ Websites

Never exaggerate.

Never invent.

---

###########################################################
# TECHNOLOGY
###########################################################

Mention technologies only where relevant.

Homepage

No.

Project pages

Yes.

Case studies

Yes.

Technical documentation

Yes.

---

###########################################################
# TONE
###########################################################

Professional

Friendly

Natural

Never too formal.

Never too casual.

---

###########################################################
# STORYTELLING
###########################################################

Every page should answer

Why?

What?

How?

Result?

What's Next?

---

###########################################################
# HUMILITY
###########################################################

Be honest about challenges.

Talk about failures.

Mention lessons learned.

Visitors trust transparency.

---

###########################################################
# CTA STYLE
###########################################################

Invite.

Never pressure.

Good

Have an idea worth building?

Let's create something meaningful together.

Bad

Hire Me Now!

Limited Time!

Contact Immediately!

---

###########################################################
# MICROCOPY
###########################################################

Loading

Preparing the experience...

404

Looks like this page hasn't been built yet.

Empty State

More experiments are on the way.

Success

Message received. I'll get back to you soon.

Error

Something went wrong. Let's try that again.

keep it.
